# 一键随机切换桌面壁纸设计

## 目标

构建一个可打包为 Windows exe 的桌面应用，技术栈为 Vue 3、Vite、Tauri 2 和 Rust。应用提供一键随机切换桌面壁纸功能，随机池包含应用内置的三张图片和用户在本次运行期间选择的本地图片。

## 范围

- 内置壁纸来源为项目当前的 `res/1.png`、`res/2.png`、`res/3.png`。
- 用户可以从界面选择本地图片加入当前运行期间的随机池。
- 用户选择的本地图片不持久化；应用关闭后清空。
- 点击“随机切换”时，从所有当前可用壁纸中随机选择一张并设置为 Windows 桌面壁纸。
- 应用需要支持通过 Tauri 打包生成 Windows exe 安装包或可执行产物。

## 推荐方案

采用 Rust 端集中处理壁纸池和系统调用的方案。Vue 前端负责展示、触发操作和反馈状态；Rust 后端负责校验图片路径、维护本次运行的用户图片列表、随机选择壁纸，并调用 Windows API 设置桌面壁纸。

这个方案把系统能力放在 Tauri/Rust 侧，前端保持轻量，后续增加校验、错误提示或更多系统能力时也更清晰。

## 架构

前端使用 Vue 3 + Vite 构建单页控制面板。页面包含内置壁纸缩略图、候选壁纸数量、随机切换按钮、选择本地图片按钮和状态提示区域。

后端使用 Tauri 2 command 暴露桌面能力。Rust 维护一个进程内状态对象，记录用户本次运行期间添加的图片路径。内置图片通过 Tauri resource 机制随应用打包，运行时解析为可被 Windows API 访问的真实路径。

Windows 壁纸设置使用 `SystemParametersInfoW`，动作参数为 `SPI_SETDESKWALLPAPER`，并使用更新用户配置与通知系统广播的标志。

## Rust 命令

- `list_wallpapers`：返回当前候选壁纸列表，包含内置图片和本次运行添加的用户图片。
- `add_user_wallpaper(path)`：校验本地图片是否存在、扩展名是否支持，加入当前运行的随机池。
- `set_wallpaper(path)`：按指定路径设置桌面壁纸。
- `set_random_wallpaper`：从当前候选池随机选择一张并设置，返回被设置的壁纸信息。

## 前端组件

- `App.vue`：页面容器，加载壁纸列表，协调用户动作。
- 壁纸缩略图列表：展示内置图和用户添加图，可点击指定设置。
- 主操作区：提供“随机切换”和“选择本地图片”两个主要操作。
- 状态提示区：展示设置成功、添加成功、校验失败或系统调用失败等信息。

## 数据流

启动时，前端调用 `list_wallpapers` 获取内置壁纸。用户点击“选择本地图片”时，前端通过 Tauri dialog 插件打开文件选择器，选择结果传给 `add_user_wallpaper`。用户点击“随机切换”时，前端调用 `set_random_wallpaper`，Rust 随机选择候选项并调用 Windows API，成功后返回当前壁纸，前端更新状态。

## 错误处理

- 未选择文件时不报错，只保持当前状态。
- 文件不存在时返回“图片文件不存在”。
- 不支持的文件类型返回“仅支持 png、jpg、jpeg、bmp”。
- Windows API 调用失败时返回系统错误信息。
- 随机池为空时返回“没有可用壁纸”；在当前设计中只要内置资源正确打包，这个错误不会出现在正常用户路径。

## 测试策略

Rust 单元测试覆盖候选池合并、图片扩展名校验、随机选择非空结果和空池错误。Windows API 设置函数通过小边界封装隔离，核心列表和校验逻辑可在不修改真实桌面壁纸的情况下测试。

前端通过构建验证和手动运行验证覆盖基础流程：启动应用、显示三张内置壁纸、添加本地图片、随机切换、指定设置、错误提示。

## 打包

使用 Tauri 2 的 Windows 打包能力。开发运行命令为 `npm run tauri dev`，构建命令为 `npm run tauri build`。构建产物位于 `src-tauri/target/release/bundle/` 下，Windows 环境会生成 exe 或安装包相关产物，具体格式由 Tauri bundler 配置决定。
